# Invariants

What must hold across every change here. Breaking one is a redesign, and a redesign is the owner's decision: propose the change and wait, never route around.

- Only configuration may break the immersion, on an explicit bail-out gesture: a right-click or the platform's application menu. What users normally believe they are doing within the terminal stays inside it, such as, if a new channel is configured to use SSH, the typing of the password, the acceptance of a key, and an SSH connection error. The terminal itself can print to stderr or log like normal terminal emulators do.
- Every change compiles on every platform the project targets. Platform-specific code sits behind a gate whose other arms exist, as per-platform implementations or a deliberate visible no-op; nothing platform-bound sits unconditionally on a shared path.
- A capability built for one platform's users doesn't cost another platform a capability it has. e.g. having russh doesn't prevent users from running ssh-agent or their system's own ssh.
- A document that tells the reader where something lives holds on every platform the project targets: the location carries the other platforms' forms beside it, or sits in a passage naming the system it speaks for, a shell transcript being one machine's and needing no translation. The rule binds the claim, not the characters: a tilde is right in a command typed into a Unix shell, and wrong as the general answer to where a file lives. First case: the install section offered three routes and all were Linux while the release carried a Windows binary, so a reader told the terminal runs on Windows was left no way to get it.
- A subsystem that carries the session somewhere else -- a transport, a multiplexer, anything putting the terminal in touch with something other than the shell it would have started on its own -- is, left unconfigured and uninvoked, indistinguishable from one not built: configuration empty, chords untouched, its startup, screen and behaviour match a build without it. First case: SSH, where an empty `[ssh]` table and no SSH chord mean a purely local terminal.
- Nothing the appliance draws of its own accord may enter the session: it takes no keystroke, writes no cell the terminal owns, and leaves nothing behind once it has stopped drawing. The glass may show what the session never sent, and does; a copy of the screen still yields only what the session sent. First case: the critters, which cross the glass unasked and are gone.
- The settings window wears the platform's stock widget look, never a theme of its own: the appliance's look is the user's choice at runtime, so no palette chosen at build time can match it; we do not even know what colour the cabinet is.
- A resource one-per-process by nature (a GPU instance, a display connection, a config watcher, the instance listener) is created once above the windows and handed down; a window owns only what dies with it. First case: a per-window VkInstance, which NVIDIA's Wayland driver answered with a process-killing segfault when a second window outlived the first one's close.
- A vendored `.tm` module is carried at a version its home published, byte for byte. A local edit under a number of our own invents a version with no release behind it, and a patch to reapply on every update; where a copy cannot be used as published, the adaptation goes in our own code and the copy stays identical to its release. Procedure: teatotal's `docs/vendoring.md`.
